# 多用户接入指南

> 目标：每个同事的 WorkBuddy（小布）用**自己的账号权限**查站点数据，互不串号。

## 一、原理速览

```
同事 A 的 WorkBuddy                        同事 B 的 WorkBuddy
   headers:                                    headers:
     Authorization: Bearer <接入令牌>            Authorization: Bearer <接入令牌>
     X-Environ-Client: <A 的随机串>              X-Environ-Client: <B 的随机串>
            │                                          │
            └──────────────┬───────────────────────────┘
                           ▼
              environ-mcp（127.0.0.1:3000）
                绑定表：clientKey → environ token
                           │  按 clientKey 取出该用户自己的 token
                           ▼
              environ-svr-v2 /openapi/**  →  InfluxDB / MySQL
```

关键点：

- **客户端标识（`X-Environ-Client`）就是「谁的电脑」的凭据**，谁在 `mcp.json` 里填谁的串
- 服务器把 environ token 存进绑定表，按客户端标识取，**所以查出来的永远是本人权限下的站点**
- 共享默认绑定默认关闭（`ALLOW_DEFAULT_BINDING=false`），**不会**出现「谁最后绑定谁的身份被所有人共用」

## 二、用户接入（三步）

### 1. 生成自己的客户端标识

```bash
openssl rand -hex 16
# 例如 3f7a1c9d2b4e5061a8c1d2e3f4a5b6c7
```

### 2. 写进 `~/.workbuddy/mcp.json`

路径：`C:\Users\<你的用户名>\.workbuddy\mcp.json`（**没有点前缀**的那个文件）

```json
{
  "mcpServers": {
    "environ-mcp": {
      "type": "streamableHttp",
      "url": "https://app.environ.online/mcp",
      "headers": {
        "Authorization": "Bearer <接入令牌>",
        "X-Environ-Client": "3f7a1c9d2b4e5061a8c1d2e3f4a5b6c7"
      },
      "timeout": 60000
    }
  }
}
```

> `type` 必须写 `streamableHttp`，写 `http` 不被识别。

### 3. 绑定账号（二选一）

**方式 A：浏览器绑定页（推荐，密码不进聊天窗口）**

打开 `https://app.environ.online/mcp/bind`，填入客户端标识 + environ 用户名密码。

**方式 B：命令行脚本**

```bash
cd <environ-mcp 目录>
node scripts/bind.js --url https://app.environ.online/mcp/bind \
                     --key 3f7a1c9d2b4e5061a8c1d2e3f4a5b6c7 \
                     --user 你的用户名
```

密码交互式输入，不回显；也可以用环境变量 `ENVIRON_PASSWORD` 传入。

**方式 C：对话内绑定（应急）**

直接对小布说「绑定 environ 账号」，它会调 `bind_user`。注意密码会留在对话记录里。

**方式 D：OAuth 标准授权（客户端支持时最优雅）**

客户端收到 `401` + `WWW-Authenticate` 后会自动打开授权页：

```
https://app.environ.online/mcp/oauth/authorize
```

你在浏览器里登录 environ 账号即可，**access_token 就是你的身份**，
之后所有查询都按本人权限执行。支持授权码 + PKCE（S256）与设备码两种流程。

绑定完成后 **重启 WorkBuddy 会话**，然后验证：

- 问小布「我现在绑的是谁」→ 应显示你的用户名与客户端标识
- 问「我有哪些站点」→ 应只看到**你自己权限下**的站点

## 三、管理员职责

| 事项 | 做法 |
|------|------|
| 分配接入令牌 | `MCP_AUTH_TOKEN` 环境变量，同一套服务共用一个 |
| 分配客户端标识 | 让每个同事自己 `openssl rand -hex 16` 生成，互不相同即可 |
| 换绑 / 解绑 | `DELETE https://app.environ.online/mcp/bind` 带 `Authorization: Bearer <接入令牌>` 与 `X-Environ-Client: <串>`；或让同事在绑定页重新绑定 |
| 查看绑定情况 | `GET /health`（带接入令牌）里 `boundClients` 是已绑定客户端数 |
| 防止串号 | 保持 `ALLOW_DEFAULT_BINDING=false`（默认值） |

## 四、常见问题

**Q：小布说「查询失败：token 无效或已过期，请重新绑定」**
A：environ 侧绑定 token 有效期 30 天。重新走一次绑定即可，客户端标识不用换。

**Q：同事之间会不会看到对方的站点？**
A：不会。查询用的永远是「当前客户端标识绑定的那个账号」的 token；没绑定就直接被拦住，不会借别人的身份。

**Q：换了账号怎么办？**
A：用同一个客户端标识重新绑定。若新账号与旧账号不是同一个人，服务器会拒绝（403），
需要管理员用接入令牌强制改绑。

**Q：能不能不写 `X-Environ-Client`？**
A：可以，但那样所有人共用「共享默认绑定」，等于共用一个账号 —— 不适合多人场景，
所以默认关闭。
