## 三、渠道 ①：官方 MCP Registry（推荐先做）

### 3.1 准备命名空间（认证身份）

命名空间决定你能不能发布，二选一：

> ✅ **本项目已于 2026-10-27 成功上架**：`online.environ/environ-mcp` v1.3.1（status: active）
> 命名空间是 `online.environ/environ-mcp` —— **注意不是 `com.environ.online/...`**，
> 原因见下方「Registry 的域名反转 bug」。remotes 仍指向 `https://app.environ.online/mcp`，
> 且这种命名空间**不做 URL 域名约束**。

| 方式 | 命名空间 | 需要什么 |
|---|---|---|
| **域名**（本项目采用） | `online.environ/environ-mcp` | 对 `environ.online` 的控制权，做 DNS TXT 验证即可 |
| **GitHub** | `io.github.<你的用户名>/environ-mcp` | GitHub 账号 + device flow 授权（国内需代理才能打开 github.com） |

**域名验证两种方式**（2026-10 已把两种都准备好了）：

```bash
# 密钥对（Ed25519）
openssl genpkey -algorithm Ed25519 -out key.pem
PUBLIC_KEY="$(openssl pkey -in key.pem -pubout -outform DER | tail -c 32 | base64 | tr -d '\n')"
PRIVATE_KEY="$(openssl pkey -in key.pem -noout -text | grep -A3 'priv:' | tail -n +2 | tr -d ' :\n')"
PROOF="v=MCPv1; k=ed25519; p=${PUBLIC_KEY}"
```

| 方式 | 做什么 | 命令 |
|---|---|---|
| **DNS TXT**（推荐） | DNS 加一条 TXT：`environ.online. IN TXT "<PROOF>"` | `mcp-publisher login dns --domain environ.online --private-key "$PRIVATE_KEY"` |
| **HTTP 文件** | 容器已内置验证端点，启动时加 `-e MCP_REGISTRY_AUTH="<PROOF>"` | `mcp-publisher login http --domain environ.online --private-key "$PRIVATE_KEY"` |

> 验证端点 `https://environ.online/.well-known/mcp-registry-auth` 与
> `https://app.environ.online/.well-known/mcp-registry-auth` **均已实测 200**。
> 一键脚本：`./scripts/registry-publish.sh --domain environ.online --mode dns`
> （私钥只落本机 `.registry-key.pem`，已加进 .gitignore）

> ⚠️ `com.<域名>/*` 的 URL 约束：remotes 的 URL 必须在该域名或其子域名下。
> `https://app.environ.online/mcp` ✓ 满足。

> 买家/审核会核对「命名空间是否对应数据持有方的验证域名」，域名方式在这一项上明显占优。

### 3.2 发布

```bash
npm install -g @modelcontextprotocol/registry-publisher

# 认证（GitHub 设备流；域名方式用 mcp-publisher login dns 或 http）
mcp-publisher login github --registry=https://registry.modelcontextprotocol.io

# 先本地校验
mcp-publisher validate server.json

# 发布
mcp-publisher publish server.json
```

### 3.3 验证已上架

```bash
curl "https://registry.modelcontextprotocol.io/v0.1/servers?search=com.environ.online%2Fenviron-mcp"
```

### 3.4 注意事项

- **`description` 必须 ≤ 100 字符**，超了 API 直接返回 422（`server.json` 里已按 40 字准备）
- **`remotes` 里绝不能写 `Authorization` 头** —— 凭据由客户端自己走 OAuth 获取；官方规范要求把凭据声明为 secret 输入，而不是填进清单
- **已发布的版本元数据不可变** —— 改配置/描述要发一个**新的版本号**
- 发布成功 ≠ 客户端一定兼容，Registry 只是元数据目录

- 保持端点在线，Smithery 会定期重新扫描

## 七、environ-mcp 特有注意事项

### 7.1 公共实例建议与内部实例隔离

现在的实例带 `MCP_AUTH_TOKEN`（预共享密钥，给内部/平台接入用）。**对外上架建议另起一个实例不设这个变量**：

```bash
-e MCP_AUTH_TOKEN=          # 留空 = 纯 OAuth
```

- 不设令牌时，鉴权层变成「只认 OAuth access_token」，客户端按标准流程走 OAuth → 登录 → 绑定自己的账号
- 静态令牌一旦泄漏，任何人拿到就能连上（虽然还得绑自己的账号，但会消耗绑定限流、污染绑定表）
- 两个实例物理隔离，nginx 用不同子域名反代即可

### 7.2 描述里不要写这些

- ❌ 任何令牌、API Key、示例凭据
- ❌ 内部主机名、内网地址（只写公网端点）
- ❌ 「数据可自由用于训练/许可」之类暗示数据权利的措辞
- ❌ 声称与某官方平台有背书关系

### 7.3 要写清楚的

- ✅ **使用者需要自己的 environ 系统账号**（每个用户绑定后只能看到自己权限内的站点）
- ✅ 数据来自环境监测业务系统，仅供内部运维与监管速查
- ✅ 当前「实时数据」因设备上报链路问题可能为空（描述别吹实时性）

### 7.4 上架前 checklist

- [ ] 后端 `environ-svr-v2` 待部署改动已上线（`userLoginWithMd5` / `bind` 支持 `passwordMd5` / `GET /openapi/session`）
- [ ] 站点搜索已支持地址/城市（后端 `StationServiceImpl.getStationsByUid` 扩字段 + LIKE 转义）

## 九、实测踩坑记录（2026-10-27）

### ⚠️ 1. Registry 的域名会「标签顺序反转」（官方 bug）

```
--domain environ.online      → 授权域变成 online.environ/*
--domain app.environ.online  → 授权域变成 online.environ.app/*
```
它实际是拿**反转后**的域名去请求验证文件：
`Get "https://online.environ/.well-known/mcp-registry-auth": no such host`

**结论**：
- 命名空间要写成 **`online.environ/environ-mcp`**（无 `com.` 前缀），并且
  **不能**写 `com.environ.online/...`（403）
- 这种命名空间**不做 remotes URL 的域名约束**，所以端点仍可留在 `app.environ.online`
- DNS 验证路径同样反转，但**登录本身能成功**（无需 nginx、无需证书）

### ⚠️ 2. 登录 JWT 只有 5 分钟有效期

`~/.config/mcp-publisher/token.json` 里的 JWT：`iat` 与 `exp` 相差 300 秒。
**login 和 publish 必须连着跑**，中间等人就会 401「token is expired」。

### ⚠️ 3. 官方 CLI 没有官方 npm 包

- ❌ `npm i -g @modelcontextprotocol/registry-publisher` → 404
- ❌ `npm i -g mcp-publisher` → 是**别人的包**（浏览器控制工具）
- ✅ 官方是独立二进制，GitHub Releases 下载；**国内直连 GitHub 极慢，走
  `https://ghfast.top/` 代理可秒下**（`ghproxy.net` 会截断成 1.8MB）
  本地已放：`environ-mcp/tools/mcp-publisher.exe`（v1.8.5）

### ⚠️ 4. `$schema` 要用当前版本

`2025-12-11`（旧的 `2025-09-29` 会提示 Deprecated，但仍能 validate 通过）。

### ✅ 实际可用的发布命令序列

```bash
cd /d/Workspace/StormWork/environ-mcp
PRIV=$(openssl pkey -in .registry-key.pem -noout -text | grep -A3 'priv:' | tail -n +2 | tr -d ' :\n')

./tools/mcp-publisher.exe login dns --domain environ.online --private-key "$PRIV" \
    --registry=https://registry.modelcontextprotocol.io   # DNS 验证，秒过
./tools/mcp-publisher.exe publish server.json               # 必须在 5 分钟内
```

## 八、验证命令（上架前自查）

```bash
U=https://app.environ.online/mcp

# 1. 未认证 → 必须 401 + WWW-Authenticate

  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}' | grep -iE 'HTTP/|www-authenticate'
```
