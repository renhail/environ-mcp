# 平台接入指南（豆包 / 扣子 / 火山引擎 / n8n / Dify …）

environ-mcp 对外提供三套入口，覆盖不同平台的接入习惯：

| 入口 | 地址 | 适合 |
|------|------|------|
| Streamable HTTP（标准） | `https://app.environ.online/mcp` | WorkBuddy、扣子 Coze、火山引擎/豆包、Dify、Claude Desktop |
| SSE（老协议） | `https://app.environ.online/mcp/sse` | 只支持 SSE 的平台（n8n 等） |
| OAuth 2.1 + PKCE | `https://app.environ.online/mcp/oauth/authorize` | 需要「用户点一下授权」的客户端 |

---

## 零、先决条件：平台没有「个人身份」，要用服务账号

WorkBuddy 这类客户端里跑的是**某个人的** environ 账号；但豆包/扣子是**平台统一**接入，
只有一个静态令牌，没有用户维度。所以平台接入必须：

1. 建一个 environ **服务账号**（或指定一个已有账号），用它能看到全部需要开放的站点
2. 给平台分配一个专属「客户端标识」（clientKey）
3. 把两者绑起来：

```bash
curl -X POST https://app.environ.online/mcp/bind \
  -H "Authorization: Bearer <接入令牌>" \
  -H "Content-Type: application/json" \
  -H "X-Environ-Client: platform-coze-doubao-001" \
  -d '{"username":"服务账号","password":"密码"}'
```

平台调用时带上 `client=platform-coze-doubao-001`，查询就以服务账号的权限执行。

## 一、扣子 Coze（coze.cn）

工作空间 → 资源库 → 插件 → 创建插件 → 类型选 **MCP 服务 / 云插件**

| 字段 | 填什么 |
|------|--------|
| MCP 服务地址 | `https://app.environ.online/mcp?client=platform-coze-doubao-001` |
| 传输方式 | Streamable HTTP |
| 鉴权方式 | Header |
| 鉴权 Key | `Authorization` |
| 鉴权值 | `Bearer <接入令牌>`（写完整，含 Bearer） |

平台侧 JSON 配置（`type` 必须是 `streamable-http`，写 `http` 不识别）：

```json
{
  "mcpServers": {
    "environ-mcp": {
      "type": "streamable-http",
      "url": "https://app.environ.online/mcp?client=platform-coze-doubao-001",
      "headers": {
        "Authorization": "Bearer <接入令牌>",
        "MCP-Protocol-Version": "2025-03-26"
      }
    }
  }
}
```

踩坑点：

- `type` 写 `http` 会导致「工具不出现」
- URL **不要带尾部斜杠**
- Header 里直接写完整的 `Bearer xxx`，不要再套一层
- 扣子建议带 `MCP-Protocol-Version` 头

## 二、火山引擎 / 豆包（volcengine.com Ark 控制台）

创建 MCP 凭证（credential）：

| 字段 | 填什么 |
|------|--------|
| `auth.type` | `static_bearer`（或 `mcp_static`） |
| `auth.mcp_server_url` | `https://app.environ.online/mcp?client=platform-coze-doubao-001`（必须 HTTPS、不能内网地址） |
| `auth.token` | 接入令牌（**不要**带 `Bearer` 前缀） |

如果平台只支持「自定义注入位置」，用 `mcp_static`：

- `injection_type` = `bearer` → 注入 `Authorization: Bearer <token>`
- `injection_type` = `query`，`injection_name` = `token` → 变成 `?token=<token>`

这两种我们服务端都支持（令牌可来自 `Authorization` 头，或 `?token=` / `?key=` / `?access_token=`）。

注意：豆包**不支持本地 stdio**，必须公网 HTTPS；插件还要走平台审核。

## 三、n8n（只支持 SSE）

| 字段 | 填什么 |
|------|--------|
| SSE URL | `https://app.environ.online/mcp/sse?token=<接入令牌>&client=<clientKey>` |
| Message URL | 服务端会通过 SSE 的 `endpoint` 事件自动下发（`/mcp/message?sessionId=…`） |

## 四、Dify

工作流 → 工具 → MCP Server：

- Transport：Streamable HTTP
- URL：`https://app.environ.online/mcp?client=<clientKey>`
- Headers：`Authorization: Bearer <接入令牌>`、`X-Environ-Client: <clientKey>`

## 五、WorkBuddy / CodeBuddy / Claude Desktop 等标准客户端

```json
{
  "mcpServers": {
    "environ-mcp": {
      "type": "streamableHttp",
      "url": "https://app.environ.online/mcp",
      "headers": {
        "Authorization": "Bearer <接入令牌>",
        "X-Environ-Client": "<你自己的客户端标识>"
      },
      "timeout": 60000
    }
  }
}
```

## 六、OAuth 2.1（标准授权，客户端支持时优先用）

### ⚠️ 前提：nginx 必须放行根路径 `/.well-known/`

MCP 规范的客户端（WorkBuddy / CodeBuddy / Claude Desktop / 官方 SDK）在做**授权服务器发现**时，
第一个候选地址固定是：

```
https://app.environ.online/.well-known/oauth-authorization-server/mcp
```

这个地址如果被 SPA 的 `try_files` 规则吃掉、返回 `index.html`（HTTP 200），
客户端会因「期望 JSON 却拿到 HTML」**直接解析失败，且不会回退到第二个候选地址**。

所以 nginx 必须加这段（已写进 `deploy/nginx.conf.snippet`）：

```nginx
location /.well-known/ {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

加完后验证：

```bash
curl -s https://app.environ.online/.well-known/oauth-authorization-server | head -c 200
# 应该输出 JSON，而不是 <!doctype html>
```

### 客户端侧怎么触发

WorkBuddy 不会「连不上就自动弹浏览器」。自定义 MCP 需要在界面上点一下：

**连接器 → 自定义连接器 → 选中该 MCP → 点「授权 / 连接」**
（对应内部动作 `mcp:beginAuthorization` → 返回 authorizeUrl → 打开浏览器 →
授权完回调走 `mcp:handleExternalOAuthCallback`）。

托管型连接器（IOA / 内置）才会自动后台授权。


服务端已实现完整规范面：

| 端点 | 地址 |
|------|------|
| 受保护资源元数据 | `https://app.environ.online/mcp/.well-known/oauth-protected-resource` |
| 授权服务器元数据 | `https://app.environ.online/mcp/.well-known/oauth-authorization-server` |
| 动态客户端注册 | `POST https://app.environ.online/mcp/oauth/register` |
| 授权端点 | `GET https://app.environ.online/mcp/oauth/authorize` |
| 令牌端点 | `POST https://app.environ.online/mcp/oauth/token` |
| 设备授权 | `POST https://app.environ.online/mcp/oauth/device_authorization` |
| 令牌撤销 | `POST https://app.environ.online/mcp/oauth/revoke` |

未授权访问 `/mcp` 会返回：

```
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer resource_metadata="https://app.environ.online/mcp/.well-known/oauth-protected-resource", scope="environ:read"
```

符合规范的客户端据此自动跳授权页 → 用户在浏览器里登录 environ 账号 → 回调带 code →
换 access_token → 之后所有 MCP 调用自动带上 access_token，**access_token 就是用户身份**
（服务端把该用户的 environ token 放在令牌里，工具调用按本人权限查数据）。

支持的授权流程：

- **授权码 + PKCE（S256）**：标准流程，`code_challenge_method` 必须是 `S256`
- **设备码（RFC 8628）**：客户端不支持跳转时用。客户端拿到 `user_code`，
  用户在 `https://app.environ.online/mcp/oauth/device` 输入验证码并登录，客户端轮询换令牌
- **刷新令牌**：`grant_type=refresh_token`，access_token 24 小时、刷新令牌 30 天

## 七、复用 environ 现有登录页（后端新增，需部署后端）

后端新增两个端点（`environ-svr-v2`，**由海林部署**）：

| 端点 | 鉴权 | 作用 |
|------|------|------|
| `GET /openapi/session` | **登录 JWT**（走正常鉴权链） | 用现有登录态换一个 30 天有效的绑定令牌 |
| `GET /openapi/me` | 绑定令牌 | 查当前绑定用户信息，确认绑定是否有效 |

于是「用户已有登录页」就能直接复用，**密码全程不经过 MCP、也不进聊天记录**：

```
environ 前端登录（拿到 JWT）
   └─> GET /openapi/session        (Authorization: Bearer <登录JWT>)
          └─> { token, userId, userName, expireDays }
                 └─> POST https://app.environ.online/mcp/bind
                        { "token": "<上一步的 token>", "userName": "<用户名>" }
                        (Header: X-Environ-Client: <客户端标识>)
                        └─> 绑定完成，之后查询按本人权限
```

MCP 侧**已经支持** `{ token }` 这种入参（见 `src/http-server.js` 的 bindHandler），
所以后端部署完就能直接用，不用再改 MCP。

## 八、运维命令速查

```bash
# 健康检查（含已绑定客户端数、OAuth 元数据地址）
curl -H "Authorization: Bearer <接入令牌>" https://app.environ.online/mcp/health

# 平台专用 clientKey 绑定服务账号
curl -X POST https://app.environ.online/mcp/bind \
  -H "Authorization: Bearer <接入令牌>" -H "Content-Type: application/json" \
  -H "X-Environ-Client: platform-coze-doubao-001" \
  -d '{"username":"服务账号","password":"密码"}'

# 解绑（删除某个平台/同事的绑定）
curl -X DELETE https://app.environ.online/mcp/bind \
  -H "Authorization: Bearer <接入令牌>" -H "X-Environ-Client: platform-coze-doubao-001"

# 查看已注册的 OAuth 客户端与活跃令牌
curl -H "Authorization: Bearer <接入令牌>" https://app.environ.online/mcp/oauth/clients
```
